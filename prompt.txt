# Hosting FrameBase for Free

Your stack: **NestJS API** (`apps/api`) + **Vite/React frontend** (`apps/web`) + **MongoDB Atlas** (already set up, cluster `uix4zly`). This guide uses three free services, one per piece:

| Piece | Service | Why |
|---|---|---|
| Database | MongoDB Atlas (you already have this) | Free M0 tier, no change needed |
| Backend API | Render (free Web Service) | Free tier runs a real Node process, unlike static-only hosts |
| Frontend | Vercel or Netlify | Free static hosting, great for Vite builds, instant deploys from GitHub |

This is genuinely $0/month, with one real caveat: Render's free tier **spins the server down after ~15 minutes of no traffic**, so the first request after a quiet period takes 30–60 seconds to "wake up." Fine for a capstone demo/portfolio project; not something you'd want for a paying customer.

---

## 1. Prep the repo before deploying

A few things need to be true first:

- **CORS**: your NestJS `main.ts` needs to allow requests from your frontend's deployed URL (not just `localhost`). Something like:
  ```ts
  app.enableCors({
    origin: [
      'http://localhost:5173',
      'https://your-frontend.vercel.app',
    ],
    credentials: true,
  });
  ```
- **Environment variables**: make sure your API reads `MONGODB_URI`, `JWT_SECRET`, `SMTP_*`, `PORT`, etc. from `process.env` — nothing hardcoded.
- **Build scripts**: confirm `apps/api` has a working `build` script (`nest build`) and a `start:prod` script (`node dist/main.js`), and `apps/web` has `build` (`vite build`) producing a `dist/` folder.
- **Atlas network access**: in Atlas → Network Access, add `0.0.0.0/0` (allow from anywhere) — otherwise Render's servers will get the same TLS/connection rejection you saw before, since they're not IP-whitelisted.
- Push all of this to GitHub — both Render and Vercel deploy by connecting to a GitHub repo.

---

## 2. Deploy the backend (NestJS) to Render

1. Go to [render.com](https://render.com) and sign up (GitHub login is easiest).
2. **New → Web Service** → connect your GitHub repo.
3. Since this is a monorepo, set:
   - **Root Directory**: `apps/api` (or wherever your NestJS app lives)
   - **Build Command**: `npm install && npm run build`
   - **Start Command**: `node dist/main.js` (or `npm run start:prod`)
   - **Environment**: Node
   - **Instance Type**: Free
4. Add your environment variables under the **Environment** tab: `MONGODB_URI`, `JWT_SECRET`, `SMTP_*`, `INVITATION_TTL`, and anything else your `.env` has locally. Never commit real secrets to GitHub — only add them here.
5. Deploy. Render gives you a URL like `https://framebase-api.onrender.com`. Note it — you'll need it for the frontend.
6. Test it directly: visit `https://framebase-api.onrender.com/api/v1/health` (or whatever health-check/simple GET route you have) and confirm you get a response, not an error.

---

## 3. Deploy the frontend (Vite/React) to Vercel

1. Go to [vercel.com](https://vercel.com) and sign up with GitHub.
2. **Add New → Project** → import the same repo.
3. Set:
   - **Root Directory**: `apps/web`
   - **Framework Preset**: Vite (Vercel usually auto-detects this)
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
4. Add an environment variable for your API's base URL, e.g. `VITE_API_URL=https://framebase-api.onrender.com`, and make sure your frontend's API client actually reads from `import.meta.env.VITE_API_URL` instead of a hardcoded `localhost:3000`.
5. Deploy. Vercel gives you a URL like `https://framebase.vercel.app`.
6. Go back to your Render backend's CORS config and add this real Vercel URL to the allowed origins (Section 1) if you didn't already know it in advance — redeploy the backend after.

---

## 4. Connect a custom domain (optional, still free)

- Vercel and Render both let you attach a custom domain for free — you only pay if you buy the domain itself (e.g. via Namecheap, ~$10/year, or use a free subdomain provider).
- If you just want something nicer than the default `*.vercel.app` / `*.onrender.com` URLs for your capstone submission, this step is optional — the default URLs work fine and cost nothing.

---

## 5. Known limitations of this free setup

- **Cold starts**: Render's free web service sleeps after ~15 min idle. First request after that takes 30–60s. If you're demoing live (e.g. to Dr. Ugwu), hit the API URL a minute or two before your demo to "wake it up."
- **Atlas M0 free tier**: 512MB storage cap, shared CPU — fine for a capstone project's data volume, not for production traffic.
- **No background jobs**: if anything in your app relies on scheduled/cron jobs, Render's free tier doesn't run background workers continuously the way a paid instance would — the free web service only runs while it's awake and handling requests.
- **Build minutes/bandwidth**: both Render and Vercel free tiers have generous but finite monthly build minutes and bandwidth — won't matter for a capstone project's traffic level.

---

## 6. Alternatives if you want to compare

- **Railway** — good developer experience, but no longer has an unlimited free tier (small monthly credit, then billed) — worth knowing if you're avoiding any card-on-file requirement.
- **Fly.io** — has a free allowance for small apps, but the setup is more involved (Dockerfile-based, CLI-driven) than Render's git-connect flow.
- **Netlify** — essentially equivalent to Vercel for the frontend piece, pick whichever you find easier.
- **Cloudflare Pages** — another solid free static-frontend option with excellent global CDN performance.

For your situation (NestJS API + Vite SPA + MongoDB Atlas), **Render + Vercel** is the least fiddly combination to set up and keep running for free.
